## Beta — read this first

**R53 Coding is beta.** I've been testing it on **my two cars**. It is not a drop-in replacement for a proven desktop NCS session yet. Until more hardware is exercised, treat every live write as experimental.

**Before you use the app on a module you care about:**

1. Take a proper **NCS Expert** backup of that module on a PC.
2. **Manually copy** the module's TRACE out of `C:\NCSEXPER\WORK\` (usually `FSW_PSW.TRC` right after a read) and **rename/keep it somewhere safe** — NCS overwrites that filename on every read. One file per module, with VIN / module / date in the name, e.g. `TL22C_BC1_20260726.TRC`.
3. Keep those TRACE files offline (USB stick, cloud, email-to-self). The phone app's `.bin` backups are useful, but they are not a substitute for a known-good NCS TRACE while this software is still beta.

### NCS Expert howtos (R53)

R53 uses chassis **R50** in NCS Expert. Read = `CODIERDATEN_LESEN` → TRACE; write = edit → `FSW_PSW.MAN` → `SG_CODIEREN`.

- [NCS Expert for beginners (NAM)](https://www.northamericanmotoring.com/forums/electrical/205937-ncsexpert-for-beginners.html) — install, cable, and the Mini coding PDFs (including **Guide II: how to read and write modules**).
- [R53 NCS Expert Guide Add-In (NAM)](https://www.northamericanmotoring.com/forums/electrical/231785-r53-ncs-expert-guide-add-in.html) — R53-specific notes (chassis **R50**, modules like BC1, read then write).
- [R53 NCS Expert Guide Additional Info (NAM)](https://www.northamericanmotoring.com/forums/electrical/245309-r53-ncs-expert-guide-additional-info.html) — more R53 setup / TRACE / NCS Dummy detail.

If you already know NCS on BMWs, the same [Dummies Guide to basic coding with NCS Expert](https://www.bimmerforums.com/forum/showthread.php?1800496-Dummies-Guide-to-Basic-coding-with-NCS-Expert) read/write flow applies — just pick **R50** and the Mini module you want.

## What it is

**R53 Coding** is the companion Android app to my [Mini R53 Logger - Flasher](/car/tech/2026/07/24/r53-logger-play-store.html) — module coding the way you'd do it in **NCS Expert**, without the Windows laptop, INPA install, and daten-file hunt. Separate APK and Play unlock from the logger/flasher; same K+DCAN cable.

Plug a standard **K+DCAN** cable into the OBD port, put a **USB-A to USB-C host (OTG)** adapter on the phone, and it talks to the modules directly. Definitions ship in the app — no files to import.

Recent builds add fault read/clear, a proper backup picker, denser everyday descriptions, and (on MRS5K) a **race seats** workflow that stages airbag Off coding from one confirmation screen.

What I still need is coverage on an **older R53** — someone who already knows NCS Expert, can take a proper desktop TRACE backup first, and is willing to compare what the app reads/writes against a known-good coding session.

## How a coding session works

Key **ON**, engine **OFF**. The live screen is short on purpose:

1. **Select a module** — Body computer (BC1), engine (EMS2000), airbag (MRS5K), cluster (KMB), DSC (MK60), etc.
2. **Read from car** — pulls the live coding indexes (shows VIN, option count, sw/var)
3. **Edit options** — full-screen list, grouped by category
4. **Write to car** — commits the change and **verifies** the block came back clean

Before any edit/write, the app saves a **`.bin` backup** named with VIN + module + timestamp (e.g. `TL22C_BC1_20260726_183413_backup.bin`). A comms log at the bottom shows TX/RX if something goes sideways.

## Edit options — live values, plain English

After a read, **Edit options** shows what the car actually has coded, not just the catalog. Settings are grouped (Features, Engine & drivetrain, Emissions & market, …). Each row has the friendly name, the NCS parameter, a short description where I've written one, and the **current** value.

![Edit options on the engine module (EMS2000)](/assets/images/r53-coding/edit-options.jpg){:.img-md}
*EMS.C04 — cruise, A/C, full-throttle compressor cut (`KLIMA_INAKTIV_BEI_VOLLGAS`), traction control. Write sits at the bottom of the list.*

Browsing and staging is free. Writing to the car is the unlock.

## Backups — restore, edit-only, or share

**Restore backup** opens a picker of every backup the phone has kept for that module. Per file you can:

- **Restore backup** — write it back to the car
- **Edit only** — open the values without writing
- **Share backup…** — export the `.bin` off the phone

## Planning mode

You don't need the car plugged in to explore what's available. **Planning mode** opens the same option lists offline — nothing on that screen talks to the car.

![Planning mode — follow-me-home and auto headlights](/assets/images/r53-coding/planning-mode.jpg){:.img-md}
*BC1 planning — `HEIMLEUCHTEN` durations, automatic headlights / AUTO detent.*

![Planning mode — lighting & fog options](/assets/images/r53-coding/planning-lights.jpg){:.img-md}
*Country variant, ECE daytime running lights, NAS dipped beam and fog behaviour.*

Modules show up as tabs. Each setting card has:

- A **plain-English title**
- The **NCS-style parameter name** (e.g. `HEIMLEUCHTEN`, `TAGFAHRLICHT_ECE`)
- A short **description** where I've been able to write one
- The actual **choices** (Off / On, time values, variants, …)

Everyday coverage includes the stuff people actually change on an R53: country variant, ECE vs NAS lighting, follow-me-home, automatic headlights / AUTO detent, DRL brightness, fog behaviour, and more. Advanced still has the long tail.

## Trouble codes

Same cable, same session: **Trouble codes — read / clear** is on the coding hub. Chassis and airbag faults use BMW hex titles (no fake SAE crosswalk on cluster / MRS / body). Handy when a coding change or a retrofit leaves a light on.

## Race seats (MRS5K)

On the airbag module, **Edit options → Race seats…** opens a dedicated track/SRS workflow so you don't hunt Advanced for sidebags, belts, and occupancy one FSW at a time.

![MRS5K Edit options — Race seats shortcut](/assets/images/r53-coding/mrs5k-edit-race-seats.jpg){:.img-md}
*Airbag (MRS5K.C08) editor — Race seats… sits above the grouped front / side / belt / occupancy lists.*

![Race seats workflow — all questions on one screen](/assets/images/r53-coding/race-seats-workflow.jpg){:.img-md}
*One screen: seat count, front bags, curtains — with a live “Will set to Off” preview before Apply.*

The pairing questions stay visible together:

1. **1 or 2 race seats** (LHD: one seat = driver side + driver belt hardware only)
2. **Steering-wheel bag and passenger dash bag** — keep On, or code Off
3. **Curtain / side-head bags** (both sides) — keep On, or code Off

A live preview lists every FSW that will go Off (both coding banks) so driver / passenger / curtain bits aren't mixed by hand. **Apply** only stages the editor; **Write to car** is still the gated step. Battery safety terminal coding is left alone on purpose — that aging yellow BST connector is a common false lead when the lamp stays on.

Track / race cars with harnesses and cages only — not for road use with stock seats and belts.

## Fine print

- **Beta software.** Live write is experimental. Do not rely on the phone alone until you've kept NCS Expert TRACE backups of every module you touch.
- **Manually extract and keep** each module's `FSW_PSW.TRC` from `C:\NCSEXPER\WORK\` after `CODIERDATEN_LESEN` — rename it and store it off the PC. NCS overwrites that filename on the next read.
- **Track / DIY use.** You're writing module configuration on a 20-year-old car. Race-seat airbag coding disables crash protection in software.
- **Backup first** — with NCS Expert (TRACE files), then with this app's `.bin` backups.
- **Key on, engine off** for live read/write. Don't code with the engine running.
